The Affine Contact-Surface Method

How the Affine mode in contact-surface.html builds a contact patch between two signed-distance fields — one cell at a time, with each body posed in its own frame. A companion to the interactive demo.

1The contact surface is an equipressure level set

Two bodies A and B each carry a signed distance field (SDF): φA(x) and φB(x), negative inside the body, zero on its surface, positive outside. Each is also given a stiffness weight wA, wB — think of it as a pressure-per-unit-penetration modulus.

Where the two weighted fields balance, we place the contact surface. That balance point is the zero set of the difference field:

D(x) = wA·φA(x) − wB·φB(x)   →   contact surface = { x : D(x) = 0 }

Raising wA makes φA "count for more," so the balance surface is pushed toward B — exactly Drake's hydroelastic equipressure patch, with SDFs standing in for pressure fields.

2Why "affine": one plane per cell

Solving D(x)=0 exactly for general fields is intractable, so space is diced into a grid of cells and each cell approximates D locally. The affine method's choice is the simplest non-trivial one: model each field inside a cell as a plane — a first-order Taylor expansion about the cell center x_c.

φA(x) ≈ φA(x_c) + ∇φA(x_c)·(x − x_c)
φB(x) ≈ φB(x_c) + ∇φB(x_c)·(x − x_c)
D(x)  ≈ D(x_c) + ∇D(x_c)·(x − x_c),   ∇D = wA∇φA − wB∇φB

Because D is now exactly linear across the cell, its zero set is an exact plane, and a plane cutting a cube gives one convex polygon. That's the whole payoff: no curved patch to approximate, so no interior "pops" as bodies move — only small O(h²) seams between cells, because neighbouring cells carry independent gradients.

The entire field for a cell is therefore just one value + one gradient per body, evaluated at the center. Steps 1–3 below are: build those (Step 1), decide whether the cell matters (Step 2), and slice the plane out (Step 3).

3Step 1 — Build the field, each body in its own frame

This is the step the pose change touched. Each body is evaluated analytically — no grid, no interpolation — but a movable body must be evaluated in its own local frame, because its SDF formula (a box's face logic, say) is only valid when the body is axis-aligned at the origin.

body A Fixed at the origin — evaluate directly

A never moves: identity rotation, zero translation. So its SDF and gradient are read straight off the analytic formula in world coordinates, with nothing to transform. In code this is the deliberately "bare" path — sdfShape(x_c, cA, …), gradShape(x_c, cA, …).

body B Movable — transform in, evaluate, rotate the gradient out

B carries a rigid pose (R, t) — a rotation and a translation. Evaluating it at a world point x_c is a three-part round-trip:

  1. Transform the query point into B's local frame: x_local = R⁻¹·(x_c − t).
  2. Evaluate B's analytic primitive there (box / sphere, axis-aligned in local space) → gives φlocal and ∇φlocal.
  3. Map back to world: the value needs no transform, the gradient does — see the two rules below.
value:    φB(x_c) = φlocal(x_local)   — identity: a rigid map preserves distance
gradient: ∇φB(x_c) = R · ∇φlocal(x_local)   — rotate the direction back into world
The key asymmetry The value is a scalar distance — a rotation and translation don't change how far a point is from a surface, so φlocal is the world value, no correction. The gradient is a direction — it was computed assuming the body was axis-aligned, so it must be rotated by R to point correctly in world space. Value: identity. Gradient: rotate. That single distinction is the whole pose change.

Spheres are exempt. A sphere's SDF and gradient are rotation-invariant, so a sphere B produces the same result with or without the round-trip — only a rotated box B differs from the old translation-only code.

4Step 2 — Which cells matter (two gates)

The cell's two per-body affine fields (the linearizations of φA and φB from Step 1) are extrapolated to its 8 corners by pure arithmetic — no new field evaluations, just a = φA(x_c) + ∇φA·e and b = φB(x_c) + ∇φB·e for each corner offset e. Their weighted difference d = wA·a − wB·b is formed at each corner too. A cell is kept only if both gates pass:

  1. Gate 1 — sign change: d is negative at some corner and non-negative at another (dMin < 0 ≤ dMax). The plane D=0 actually cuts the cell.
  2. Gate 2 — real overlap: some corner has a < 0 and b < 0 — it's genuinely inside both bodies.
Why gate 2 is needed D is a difference of two weighted fields, so it can cross zero far out in empty space where the fields happen to balance but neither body is present. Gate 1 alone would light up a whole trailing band of those phantom cells; gate 2 keeps only cells inside the true geometric overlap.

Because the corner extrapolation uses world-space gradients and world offsets, this step is automatically correct for a rotated B — nothing here changed.

5Step 3 — Slice the plane into a polygon

For a surviving cell:

  1. Edge crossings. Walk the 12 cube edges; wherever d changes sign, place the crossing by linear interpolation. This is exact, not approximate, because D is affine inside the cell. Both φA and φB are carried along the interpolation for the clip step.
  2. Order the ring. All crossings lie on one plane (D=0 is linear), but come out in arbitrary edge order — project into an in-plane basis and sort by angle to form a convex polygon.
  3. Trim (optional). Clip the polygon to the real overlap with Sutherland–Hodgman: once against φA ≤ 0, once against φB ≤ 0.
  4. Emit. Keep the raw polygon for the outline; fan-triangulate it for the rendered mesh.

6The whole cell, in pseudocode

Mirrors affineEmit in contact-surface.html:

// poseB = (R, t) built once per frame from the Euler sliders; A is identity.
for each cell with center x_c, size h:
    // --- Step 1: field build ---
    φA, ∇φA = sdf/grad of A at x_c            // bare — A fixed at origin
    xL      = R⁻¹·(x_c − t)                    // B: point into local frame
    φB      = sdfLocal(xL)                     // value: no transform back
    ∇φB     = R · gradLocal(xL)                // gradient: rotate back
    Dc      = wA·φA − wB·φB
    ∇D      = wA·∇φA − wB·∇φB

    // --- Step 2: extrapolate to 8 corners, gate ---
    for each corner offset e:
        a = φA + ∇φA·e ; b = φB + ∇φB·e ; d = Dc + ∇D·e
    if not (min d < 0 ≤ max d)            : skip   // gate 1: sign change
    if not (any corner has a<0 and b<0)   : skip   // gate 2: real overlap

    // --- Step 3: slice + emit ---
    crossings = exact D=0 points on the 12 edges
    poly      = orderRing(crossings)
    if trim: poly = clip(poly, a≤0); clip(poly, b≤0)
    emit poly  // outline + fan-triangulated mesh

7How the other modes differ

The demo's MC / MC33 / MT modes reach the same field D = wAφA − wBφB, but source φB differently — and that's the only real difference between the pipelines:

ModeHow φB is obtainedRotation handling
Affineanalytic, per cell center, exactpoint → local, gradient rotated back
MC / MC33 / MTbaked on B's grid, trilinearly resampled at A's cornersgrid baked in B's local frame; sample transforms the query point in

Both share one pose layer, so rotating B keeps all four modes consistent. The MC/MT family keeps its deliberate resampling error (that's what the demo's "SDF fit" inset exists to show); affine stays fully analytic with no grid.

8Trade-offs in one breath

  • Wins: each cell's patch is an exact plane-cube slice — no fixed-triangulation topology flips (MC's interior pops), no tet artifacts (MT's fix for them). Triangles are born at zero area and grow smoothly as bodies move.
  • Cost: neighbouring cells compute independent gradients from their own centers, so their planes don't perfectly meet — O(h²) seams at cell boundaries instead of one continuous surface. Refining the grid shrinks the seams.
  • Requirement: needs a value and a gradient per body per cell. Trivial for analytic primitives (closed-form gradient); for a baked/mesh body it would need a baked gradient field or finite differences — the analytic path sidesteps that entirely.
